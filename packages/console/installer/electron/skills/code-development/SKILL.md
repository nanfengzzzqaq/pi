# 代码开发工作流

只在用户要求处理代码、仓库、Git 或 GitHub 时使用本技能。

## 标准顺序

1. 先识别工作区、项目类型、仓库状态和现有说明文件。
2. 修改前读取相关代码，不覆盖用户已有的无关改动。
3. 需要新分支时使用结构化 Git 工具建立分支。
4. 使用读取、搜索、编辑和写入工具完成最小必要修改。
5. 根据项目文件识别所需环境；环境缺失时说明原因，并使用代码开发插件安装对应组件。
6. 运行与改动相关的检查或测试，报告真实结果。
7. 提交前展示文件列表和代码差异，区分本轮修改与原有修改。
8. 只有用户明确要求提交时才提交；只有用户明确要求推送时才推送。
9. 推送后报告仓库、分支、提交和远端结果。创建拉取请求时给出链接。

## 工具选择

- 文件理解与修改：读取文件（read）、搜索文件内容（grep）、查找文件（find）、编辑文件（edit）、写入文件（write）。
- 仓库状态与差异：仓库状态（git_status）、查看代码差异（git_diff）。
- 分支：管理代码分支（git_branch）。
- 提交：提交代码（git_commit）。
- 同步：同步代码仓库（git_sync）。
- GitHub 仓库：管理 GitHub 仓库（github_repository）。
- 拉取请求与检查：管理拉取请求（github_pull_request）。
- 项目环境：管理开发环境（development_environment）。

不要把安装环境、提交、推送或创建拉取请求伪装成普通文本回复；必须实际调用相应工具，并以工具结果为准。
