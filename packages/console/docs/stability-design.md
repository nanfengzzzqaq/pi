# Pi Console 0.3.51：全栈优化设计与实施说明

本次目标是让现有 Pi Console 更稳定、更容易使用，维持原生 JavaScript、Node HTTP、按需能力包和本地优先的结构。范围包括聊天、前端展示、会话生命周期、模型和登录、编辑器、附件、持久化、桌面边界、更新和发布。本文区分已经实现的改动与仍需独立验证的后续设计；没有把“全栈优化”理解为替换全部架构。

## 1. 设计原则

1. 首屏围绕对话、当前模型和输入框；更多能力由工作台、工具目录和设置承载。
2. 用户内容优先：没有确认保存成功，就不能标记为已保存；损坏数据不能自动当作空数据覆盖。
3. 异步结果必须归属于发起它的文件或会话；晚到的响应不能改变用户后来选择的内容。
4. 恢复必须有明确边界：能够验证的备份自动恢复，不能验证的原文保留并报错。
5. 只增加能说明收益的小模块，不引入新的 UI 框架、数据库或后台服务。
6. 优化要能验证：使用真实函数、真实本地 HTTP 和合成浏览器场景；账号额度和模型服务行为另行验证。

## 2. 界面与交互

| 区域 | 本版行为 | 设计依据 |
| --- | --- | --- |
| 主聊天 | 保留现有视觉体系和空状态；统一隐藏规则 | 隐藏的提示、停止图标和面板不会被组件样式意外显示 |
| 模型栏 | 按服务商分组，可搜索名称和来源 | 多账号、多系列模型仍使用一个选择器，无需新增管理页面 |
| 小窗口 | 模型栏自然换行，搜索与管理入口继续可用 | 重要入口不因窗口变窄而消失 |
| 可读性 | 模型选择和辅助按钮字号、对比度适度提高 | 不改变整体信息密度 |
| 空会话 | 明确显示“暂无历史对话” | 空数组也是加载完成，不能一直显示加载中 |
| 差异审查 | 编辑器“查看差异”和工作台“差异”入口接通 | 复用已有差异组件，避免另建一套编辑器 |
| 设置与预览 | 对话框语义、Tab 焦点约束、Escape 关闭；返回合理焦点 | 键盘使用者也能完成配置和预览 |
| 提示 | 连接与反馈带状态语义；错误和成功提示的旧定时器互不覆盖 | 避免新错误被较早的提示计时器提前隐藏 |

深浅主题和 960、1280、1440 像素窗口均纳入浏览器检查。测试使用真实 HTML/CSS/app.js 与模拟 API；不能等同于所有缩放比例、屏幕阅读器或真实安装环境的完整认证。

## 3. 输入、草稿和发送

- 中文输入法的候选确认 Enter 不发送，普通 Enter 发送，Shift+Enter 换行。
- 文字草稿按会话保存在本机浏览器存储中；附件草稿在当前应用进程内按会话保留。附件内容不会重复塞进 localStorage。
- 切换会话前保存草稿；发送失败恢复待发内容。旧会话的延迟上传或发送结果不能覆盖新会话的草稿。
- 同一会话有待提交消息时避免重复提交；读取附件期间提示稍后发送。
- 前端预检每条消息最多 32 个附件、单文件 20 MiB、总量 50 MiB；服务端独立校验，前端提示不作为安全边界。
- 新建对话期间按钮暂不可重复点击，较早的导航请求完成后不会抢回当前会话。

文字草稿的自动保存降低意外关闭损失，但不是跨电脑同步。关闭后重新打开，尚未上传的附件需要重新添加。消息请求如果已经被服务端接受、随后网络断开，仍应以恢复出的历史为准；本版未引入全链路消息幂等 ID。

## 4. 历史、实时输出和性能

连续文本输出改为约 60 ms 的节流刷新，结束时补齐尾部。原来的尾沿防抖在持续收到内容时会不断推迟显示。历史恢复期间集中进行折叠和滚动计算，避免每加入一条消息都扫描整个列表。

默认加载最近约 100 条历史记录，并保留轮次边界；用户可继续加载更早消息。加载后会展示前面的内容，不跳回最新消息。产物解析按轮次收集并批量请求，每批最多 100 组，避免每个 assistant 片段单独发一次请求。后台状态轮询在页面不可见时跳过，并避免上一次尚未完成就重叠执行。

在一次短文本合成场景中，1000 条交替用户/助手消息的首屏渲染，从审查时约 559 ms、500 次产物请求，降到数毫秒量级、100 个消息节点和 1 次批量请求。这是同一浏览器测试夹具下的局部指标，收益来自首屏只加载近期历史；不是对完整 1000 条逐条渲染速度的承诺。单个超长轮次可能超过 100 条，服务端目前仍先构造历史再截取，仍有进一步优化空间。

实时事件携带本次会话运行实例标识。重启后序号重置、游标超前或缓冲裁剪时，服务端要求客户端重新读历史；客户端先完成快照再续接事件，避免旧快照盖掉新输出。连接带心跳，按响应关闭清理资源；过慢客户端的发送缓冲过大时断开，让其走恢复流程。

## 5. 编辑器和文件

保存操作记录文件对象、内容版本和当时文本。保存期间继续输入，返回成功仅更新已落盘版本，后来新增的文字仍显示“有未保存修改”。不同文件之间的请求独立，旧文件保存结果不会改变新文件状态。

打开其他文件时，旧内容仍使用旧文件标题；读取期间发生新的编辑，需要再次确认才切换。同一文件再次点击不会重新读取并丢弃未保存内容。Monaco 资源加载失败后可以重试。

文本写入使用同目录独占临时文件，完成写入和刷盘、再次核对原文件 SHA 后替换。保留 UTF-8 BOM、UTF-16 字节序以及现有 POSIX 模式；编辑符号链接时更新其真实目标并保留链接。检测到外部修改、刷盘失败或替换失败时，不把原文件截断。Windows 自定义 ACL、硬链接语义及网络文件系统的替换行为需要额外环境验证，不能把原子替换称为所有文件系统上的完整事务。

关闭客户端前检查编辑器未保存内容；自动更新安装接管前也再次检查，避免下载期间新增的编辑被关闭。文件树加载和搜索只接受最新请求的结果。

## 6. 附件和原始副本

上传接口保存工作副本与原始快照，返回小型图片引用；消息发送时服务端从合法位置读取图片。这样一张几 MB 的图片不会在上传后又被 Base64 填入默认 1 MiB 的普通消息请求中。

图片引用只接受当前会话的快照目录或当前工作区 uploads 中的文件，校验真实路径，支持合法目录链接，同时拒绝越界链接和其他会话快照。支持 PNG/JPEG/GIF/WebP 作为模型图片；SVG 仍可作为文件附件处理。上传 JSON 上限包含 Base64 膨胀，普通请求上限保持 1 MiB。错误 JSON、非对象 JSON 返回 400，超限返回完整的 413 响应。

附件索引改为结构与路径校验、临时文件原子保存、有效备份恢复。损坏原文另外保留，找不到有效备份时停止覆盖。模型修改工作副本后，历史消息仍可指向原始快照。本版没有增加上传数据库；磁盘中途失败可能留下未关联的副本，自动回收必须另行设计引用检查，不能按文件时间直接删除。

## 7. 会话和模型生命周期

- 预热会话加载扩展后释放自身资源；测试确认不会撤销已经注册的 Antigravity provider。
- 用户选择模型或思考等级时明确持久化默认值，新对话沿用选择。
- 模型鉴权切换有进行中状态，避免与发送、再次切换和删除交错。
- 删除先等待模型切换、消息预处理与运行中任务收敛，再释放会话、删除记录，工作区保留。
- 每次发送更新最近使用时间；索引写入失败时不能先回复已接受再让任务消失。
- 索引以有效 JSON、备份和损坏原文三类文件管理；恢复错误不会静默产生空列表并覆盖历史。

Google Antigravity 和 Codex 使用各自 provider 记录，API Key 编辑与 OAuth 共用同一文件锁。所有相关读取与修改都在锁内检查原文；空文件、数组、null、原始值或损坏 JSON 不会被当成新账号配置覆盖。这里只显示账号已有模型，搜索或分组不会赋予额外模型权限；实际可用性仍由提供方账号和额度决定。

## 8. 数据迁移

流程为：检查目标为空及目录关系 → 复制到独立暂存目录 → 固定 64 KiB 缓冲逐块核对 → 改写内部数据路径 → 安装新目录 → 原子更新位置指针 → 请求重启。

非空目标拒绝覆盖；任务、账号登录、安装或其他修改进行中拒绝迁移。原数据目录保留。只忽略数据根下的一次性更新缓存，用户项目内部名为 update 的目录仍复制。普通文件之外的链接和特殊文件会明确报错，不猜测应该迁移链接还是目标。

复制失败清理本次暂存目录；最后的位置指针切换失败时，旧位置继续有效，新副本保留供恢复。成功后当前进程停止接收继续修改旧位置的 API，重启再使用新位置。本版仍为同步迁移，大数据目录复制期间窗口可能短暂不响应，后续后台任务化见下表。

## 9. 桌面与本地服务边界

桌面每次启动生成随机连接令牌，经受信任主页面的 IPC 交给前端，仅存于内存。IPC 同时检查主窗口 WebContents、主 frame 与精确的应用页面 URL；同源文件预览、子 frame 和其他窗口不能获取桌面能力。

本地 API 校验回环 Host、当前端口和浏览器来源。文件原始读取设置禁止 MIME 猜测及沙箱响应头，HTML/XML/SVG 以附件下载处理。下载、普通 API、事件流和 PDF 使用同一桌面鉴权来源，桌面鉴权失效提示重启，不让用户输入一个会被内存令牌覆盖的无效值。

这是阻止普通网页借用本地权限的边界，不是隔离已获授权的模型工具或恶意本机程序。独立开发服务器仍支持显式 PI_CONSOLE_TOKEN 配置；本版没有把服务开放到公网。

## 10. 更新、打包与维护

下载要求可信摘要；校验长度和 SHA-256 后才进入安装。重试缓存安装包再次校验，旧缓存缺少摘要时要求重新下载。更新启动前检查任务状态，更新进行时暂不接受新的修改请求；安装接管失败保留可恢复状态。

安装包关键资源检查扩展到本次新增模块、持久化模块、样式、主进程及两个 preload。源码与安装版副本保持一致，避免开发代码正确但实际发布旧文件。

常规发布的新建草稿可能尚未出现在分页清单中。本版仅在清单没有受管草稿且没有冲突时，对首次检查最多尝试 6 次、间隔 2 秒；不同 ID、多份草稿、归属不符、tag 变化和资产不符仍立即失败。有限等待不证明此前每次失败都由一致性延迟造成，实际发布还需观察。

Console 版本为 0.3.51，不改变下游独立发布方式或上游包的版本线；锁文件只更新 Console 版本元数据。本次没有升级外部依赖。

## 11. 仍需后续验证的设计

| 领域 | 当前限制 | 后续最小方案与启用条件 |
| --- | --- | --- |
| 主进程响应 | HTTP 与部分同步磁盘操作仍在 Electron 主进程 | 先测大型目录/历史下的输入延迟；出现持续阻塞后，将文件索引、迁移移到受控 worker，桌面权限桥留在主进程 |
| 会话内存 | 已恢复会话尚无空闲淘汰上限 | 仅淘汰无 SSE、无任务、无模型切换的空闲会话；恢复测试证明扩展无状态损失后再启用 |
| 大历史 | 服务器先构造历史再截取，超长轮次仍可能很大 | 以稳定消息 ID 和游标从存储层分页；跨页工具调用关联与滚动位置先通过测试 |
| 账号落盘 | 上游 AuthStorage 后端仍持锁直接写文件 | 独立处理原子替换与 Windows ACL/文件监测兼容；本版已防并发丢更新和损坏覆盖，但不承诺断电事务性 |
| 消息重试 | 网络中断可能造成“已接受但响应丢失” | 请求 ID 加持久化去重记录，重新提交同一 ID 返回原结果；前后端共同实施 |
| 上传内存 | 上传仍一次 Base64 JSON，50 MiB 上限会有额外内存开销 | 实测峰值超出预算后改流式上传；保留大小、类型、会话归属与原始快照校验 |
| 迁移与工作区 | 同步迁移；切换工作区原有文件合并规则未全面改造 | 长操作显示真实进度；冲突先列清单、明确选择，禁止静默覆盖；链接、外部程序并发写入需单独处理 |
| 配置一致性 | 自定义模型配置与账号文件不是跨文件事务 | 对失败提供明确重试和差异；达到实测故障条件后引入小型写入日志，而非直接更换数据库 |
| 历史语义 | 部分工具标签、能力信息仍由当前版本推导 | 持久化每轮实际模型与能力快照；老记录明确标记未知，避免伪造历史 |
| 界面维护 | app.js 和 style.css 仍较大、存在历史样式叠加 | 按聊天/模型/文件/设置逐块抽取原生模块；每次保持旧路由和 DOM 契约，避免一次重写 |
| 诊断 | 已有日志不足以覆盖所有现场性能问题 | 增加本地、可清除、默认脱敏的耗时和错误计数；不记录提示词和凭据，不默认上传 |
| 跨电脑 | 各电脑独立保存配置与授权 | 保持更新项目后本机配置；若以后要求同步，单独设计可选配置导出，默认不导出令牌或附件 |

这些事项有明确设计和验收条件，但本版没有宣称已经完成其实现。保留现有稳定边界比一次引入多套状态、迁移和后台服务更符合 Pi 的极简理念。

## 12. 验证与发布验收

本地执行仓库完整静态/类型/依赖与浏览器入口检查，离线构建，并运行持久化、账号、HTTP、SSE、编辑器、生命周期、模型集成、桌面权限、更新和安装包相关的命名回归测试。HTTP 测试使用真实回环服务，浏览器测试使用真实前端源码及模拟服务，不调用付费模型。

发布还必须通过 GitHub 的 Linux 检查与 Windows 构建，验证最终资产版本、来源提交、长度和摘要。本地测试通过不代表已经发布成功；实际发布状态以 GitHub Release 与运行记录为准。

实际 Google/Codex 账号的重新登录、真实模型回复、用户工作区与 Windows 安装接管应在用户本机更新后验证。本次未读取或移动用户真实账号凭据，也未调用用户的付费模型额度。
